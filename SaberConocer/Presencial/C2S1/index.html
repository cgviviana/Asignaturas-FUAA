2.1 Recopilación y preparación de datos para la solución

En este tema se define qué información necesita la aplicación, cómo se captura, cómo se organiza en tablas y qué reglas permiten convertir los registros en información útil.

Contenido

1. ¿Cómo funciona la solución?

El problema es el ingreso tardío a la primera hora de clase. La solución registra la hora real de llegada, distingue los retardos justificados de los que sí se contabilizan y permite hacer seguimiento según la normativa institucional.
1. Información institucionalLa aplicación consulta estudiantes, docentes, asignaturas, grupos, inscripciones y horarios.
2. Apertura de la claseEl docente abre la clase correspondiente a la primera hora. La aplicación genera el QR asociado a esa clase.
3. Registro de llegadaEl estudiante inicia sesión institucional y escanea el QR. Si necesita apoyo porque no puede usar su dispositivo, el docente registra la llegada manualmente.
4. Cálculo del retrasoEl sistema compara la hora de llegada con la hora programada de inicio y calcula los minutos de retraso.
5. JustificaciónCuando existe una justificación válida, el evento queda registrado, pero no se suma al conteo de retardos para seguimiento.
6. SeguimientoLos retardos sin justificación válida se acumulan y la aplicación muestra la acción que corresponda según la normativa institucional.
7. Acciones progresivasLa solución puede apoyar una secuencia como llamado de atención, comunicación con familia o acudiente y la medida definida por el reglamento.
8. Análisis de patronesEl tablero permite observar concentraciones de retardos por día, grupo, asignatura, docente o motivo reportado.

2. De los registros a la base de datos

Durante el uso de la aplicación se generan muchos registros. El conjunto organizado de esos registros forma una base de datos: una colección de información que puede consultarse, relacionarse y utilizarse después.
AcciónEl estudiante E014 escanea el QR de la clase C102 a las 07:12.
→
RegistroSe guardan por separado el estudiante, la clase, la fecha, la hora y el método de registro.
→
Base de datosEse registro se guarda junto con los demás registros de estudiantes, clases, llegadas y justificaciones.
Dato estructurado: cada valor ocupa un campo definido. En lugar de guardar una frase como “E014 llegó a C102 a las 07:12”, se guardan valores separados: ID_estudiante = E014, ID_clase = C102, hora_captura = 07:12.
Modelo de datos: es el plano que define qué información necesita la base de datos, en qué tablas se guarda y cómo se relacionan esas tablas. En este proyecto, el modelo conecta una llegada con el estudiante, la clase, el grupo, la asignatura, el docente, la justificación y el seguimiento.

3. ¿Cómo se organiza la base de datos?

Una tabla agrupa registros del mismo tipo. Cada fila representa un registro y cada columna representa un campo. El modelo de datos utiliza varias tablas porque la aplicación maneja diferentes tipos de información.

Estudiantes

Una fila por estudiante. Campos como ID_estudiante, nombre y correo.

Docentes

Una fila por docente. Campos como ID_docente, nombre y correo.

Asignaturas

Una fila por asignatura. Permite saber qué materia corresponde a cada grupo.

Grupos

Una fila por grupo o NRC. Se relaciona con una asignatura.

Inscripciones

Relaciona estudiantes con los grupos en los que están matriculados.

Clases

Una fila por sesión de clase. Guarda grupo, docente, fecha y hora de inicio.

Llegadas

Una fila por registro de llegada. Guarda estudiante, clase, hora y método de registro.

Justificaciones

Relaciona una llegada con el motivo, soporte y resultado de la validación.

Seguimientos

Registra las acciones aplicadas según el número de retardos contabilizados.

5. Cálculos, justificaciones y seguimiento

Los datos capturados permiten calcular el retraso y decidir si ese evento se contabiliza. Después, el historial de retardos contabilizados permite aplicar el seguimiento establecido por la normativa institucional.
Datos capturados
hora_inicio = 07:00
hora_captura = 07:12
→
Cálculo
07:12 − 07:00 = 12 minutos

Resultado
minutos_retraso = 12
Justificación
Si la justificación cumple los criterios establecidos, justificación_válida = TRUE.
→
Conteo
El evento queda registrado, pero cuenta_como_retardo = FALSE. Si no existe una justificación válida, el retardo sí se suma al historial.
CampoCómo se obtieneRegla
minutos_retrasoCalculadoDiferencia entre hora_captura y hora_inicio, con mínimo de 0
llegó_tardeCalculadoTRUE cuando minutos_retraso > 0
justificación_válidaValidación del soporteTRUE cuando la justificación cumple los criterios definidos
cuenta_como_retardoCalculadoTRUE cuando llegó_tarde = TRUE y justificación_válida = FALSE

6. Limpieza de datos

La limpieza de datos consiste en corregir los registros para que puedan utilizarse con seguridad en la aplicación. Cada problema debe tener una acción concreta de corrección.
Campo obligatorio vacíoEj.: falta ID_estudiante.Consultar la fuente institucional y completar el dato antes de cargar el registro. Si el dato no puede recuperarse, se descarta ese registro y se realiza una nueva captura correcta.
Campo opcional vacíoEj.: el estudiante no presentó soporte.Mantener el campo vacío porque ese dato no existe para ese registro.
Registro duplicadoMismo estudiante, clase y momento de registro.Comparar los registros y conservar una sola versión del evento válido.
Formato diferenteFecha u hora registrada con otra estructura.Convertir el valor al formato definido para ese campo antes de utilizarlo.
Valor imposibleEj.: una hora como 27:80.Verificar el dato en la fuente original. Si existe el valor correcto, reemplazarlo; si no puede verificarse, retirar ese registro de los cálculos y volver a capturarlo.
Valor fuera de catálogoEj.: motivo escrito de distintas formas.Reemplazarlo por una de las categorías definidas para mantener consistencia en los análisis.
En este proyecto: primero se revisan los datos institucionales que alimentan el modelo. Después se revisan los registros generados por la aplicación: clases, llegadas, justificaciones y seguimientos.
