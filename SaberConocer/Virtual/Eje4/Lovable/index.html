Frontend y backend

Son las dos partes principales de una aplicación.

Frontend

Es lo que la persona ve y toca: inicio de sesión, botón Escanear QR, formularios, historial y dashboard.

Backend

Es lo que trabaja detrás: guarda datos, identifica usuarios, consulta sesiones y devuelve información.

Estudiante pulsa “Escanear QR”→ Frontend recibe la acción→ Backend guarda y consulta→ Frontend muestra el resultado
En este proyecto, Lovable construye la interfaz y conecta la lógica de la aplicación. Supabase será la plataforma donde administraremos los datos y usuarios que trabajan detrás.

Prompt del proyecto

Lo llamamos “prompt maestro” porque es la primera instrucción grande y completa con la que Lovable entiende el proyecto antes de empezar a construir. Aquí reunimos problema, usuarios, tablas, flujo, UX y funciones.

Crea una aplicación móvil responsive, moderna, intuitiva y visualmente atractiva para el CONTROL DE RETARDOS DE ESTUDIANTES DE UN COLEGIO. ## CONTEXTO DEL PROYECTO La solución ya fue diseñada previamente. Se cuenta con: - definición del problema y de la solución; - flujo del algoritmo; - diseño UX con pantallas, navegación, wireflow y wireframes; - estructura de datos organizada en tablas. Usa estos elementos como base para construir la aplicación. ## DATOS La aplicación trabajará con las siguientes tablas: - Usuarios - Estudiantes - Matrículas - Cursos - Sesiones - Registros - Gestión - Parámetros - Resumen Estas tablas deben quedar relacionadas para identificar correctamente usuario, rol, estudiante, matrícula, curso, sesión y registro de llegada. Usa Supabase para almacenar y consultar estos datos. ## USUARIOS Y ACCESO La aplicación tendrá tres perfiles: 1. Docente 2. Estudiante 3. Coordinador Al iniciar sesión mediante correo electrónico, identifica automáticamente al usuario y determina su rol. Después del inicio de sesión, muestra únicamente las funciones correspondientes a ese usuario. ## PERFIL DOCENTE Cuando ingrese un docente: - identifica automáticamente sus datos; - consulta los cursos y sesiones que tiene asignados; - muestra claramente la clase o sesión correspondiente; - muestra curso, fecha, horario y demás información disponible; - permite iniciar la sesión de asistencia; - genera automáticamente un código QR único para esa sesión de clase; - el QR debe identificar la sesión; - muestra el QR grande en pantalla para que los estudiantes puedan escanearlo; - permite consultar en tiempo real los estudiantes que ya registraron su llegada. El docente también debe poder realizar un REGISTRO MANUAL DE LLEGADA cuando un estudiante no pueda utilizar el QR, no tenga conexión a Internet, haya tenido cambio de jornada o exista alguna novedad. Cuando el docente haga este registro, debe quedar identificado como REGISTRO MANUAL REALIZADO POR DOCENTE. ## PERFIL ESTUDIANTE Cuando ingrese un estudiante: - identifica automáticamente sus datos mediante su correo; - consulta su información en Estudiantes y Matrículas; - muestra su nombre, curso y datos correspondientes; - presenta como acción principal el botón “Escanear QR”; - permite utilizar la cámara del teléfono para leer el QR generado por el docente. Cuando escanee el QR: 1. identifica al estudiante; 2. identifica la sesión de clase; 3. identifica el curso; 4. obtiene automáticamente la fecha; 5. obtiene automáticamente la hora real de llegada; 6. consulta la hora programada de la sesión; 7. calcula los minutos de diferencia; 8. determina automáticamente si llegó A TIEMPO o con RETARDO; 9. guarda el registro en Supabase. Después del registro muestra una confirmación clara, por ejemplo: ASISTENCIA REGISTRADA Hora de llegada: 7:08 a. m. Retardo: 8 minutos. El estudiante también debe poder consultar su historial de asistencias y retardos y, cuando corresponda, registrar o consultar el motivo y estado de una justificación. ## PERFIL COORDINADOR Cuando ingrese un coordinador, muestra un DASHBOARD ADMINISTRATIVO COMPLETO. Debe poder visualizar como mínimo: - total de retardos; - estudiantes con retardos; - estudiantes reincidentes; - cursos con mayor cantidad de retardos; - retardos por curso; - retardos por estudiante; - retardos por día; - días de la semana con mayor número de retardos; - minutos acumulados de retardo; - motivos de retardo; - retardos justificados y no justificados; - tendencias de retardos en el tiempo. Incluye gráficos claros y fáciles de interpretar. Permite filtrar la información por: - fecha o rango de fechas; - curso; - estudiante; - estado de asistencia; - estado de justificación. Genera una ALERTA VISUAL cuando un estudiante acumule 3 o más retardos. ## DISEÑO DE LA APLICACIÓN La interfaz debe parecer una aplicación móvil real. Utiliza: - diseño limpio y educativo; - fondo claro; - tarjetas modernas; - bordes redondeados; - iconos sencillos; - tipografía muy legible; - buen contraste; - navegación inferior tipo aplicación móvil; - botones grandes para las acciones principales; - gráficos modernos para el dashboard; - diseño optimizado principalmente para teléfonos móviles. Incluye el LOGO DEL COLEGIO en la pantalla de acceso y en el encabezado de la aplicación. [PEGAR AQUÍ EL LOGO O INDICAR EL NOMBRE DEL COLEGIO] Utiliza los colores institucionales del colegio. ## PANTALLAS PRINCIPALES ACCESO - Logo. - Nombre del sistema. - Inicio de sesión con correo. ESTUDIANTE - Inicio. - Escanear QR. - Confirmación de llegada. - Historial. - Justificaciones. - Perfil. DOCENTE - Inicio. - Clase/sesión actual. - Generación y visualización del QR. - Estudiantes registrados. - Registro manual. - Novedades. - Historial. COORDINADOR - Dashboard. - Estudiantes. - Cursos. - Registros. - Alertas. - Justificaciones. - Reportes. ## FUNCIONAMIENTO PRINCIPAL Construye primero una versión funcional y responsive con: - los tres perfiles; - inicio de sesión; - flujo de QR; - registro automático de hora; - cálculo de retardos; - registro manual del docente; - historial del estudiante; - dashboard del coordinador; - conexión con Supabase. Al terminar la primera versión, muéstrala en la vista previa para revisar navegación y funcionamiento antes de realizar ajustes adicionales.

Conectar Supabase

Primero abrimos Supabase en otra pestaña del navegador y creamos el proyecto. Después volvemos a Lovable para conectarlo.

1
Abrir Supabase y crear un proyecto para Control de Retardos.
2
Crear o importar las tablas que ya definimos.
3
Volver a Lovable.
4
Abrir la opción de conexión con Supabase dentro del proyecto.
5
Autorizar la cuenta y elegir el proyecto de Supabase.
6
Pedir a Lovable que use esas tablas en formularios, login y dashboards.
A partir de este momento, cuando la app registre una llegada, podremos ir a Supabase y ver la fila guardada.

Revisiones y ediciones

Cuando algo necesita ajuste, lo revisamos y pedimos cambios concretos.

History

Permite revisar versiones anteriores del proyecto.

Visual Edits

Permite seleccionar elementos en la vista previa y ajustar texto, tamaño, color o espaciado.

Ejemplo: “En el dashboard del coordinador agrega una tarjeta de reincidencias con estudiantes que tengan 3 o más retardos usando los registros de Supabase. Conserva el diseño actual.”
